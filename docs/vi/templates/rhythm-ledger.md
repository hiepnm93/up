# Mẫu Sổ Ghi Nhịp Độ

Hãy chép sổ này vào một ghi chú riêng tư và dùng một trang mỗi tuần. Đây không phải là bảng chuỗi ngày liên tiếp hay bảng điều khiển để chấm điểm bản thân. Nó giúp bạn thấy điều gì xứng đáng được giữ lại, điều kiện nào cần thay đổi, và cách quay trở lại sau một lần gián đoạn.

Nếu sổ đã chỉ ra một trở ngại, hãy dùng bảng xử lý sự cố và hai ví dụ trong [Kỷ luật và Tính nhất quán trong Thực hành](../threads/practice/discipline-and-consistency.md), sau đó xác định một thay đổi cùng tiêu chí chấp nhận cho thay đổi đó trong [Kế hoạch Duy trì Tính nhất quán](consistency-plan.md). Thẻ thử nghiệm đó là phần bổ sung cho sổ này. Hãy đưa kết luận của nó trở lại mục "Quyết định của Tuần này" thay vì duy trì thêm một lịch trình riêng.

Đừng ghi lại mật khẩu, giấy tờ tùy thân, dữ liệu khách hàng, thông tin y tế riêng tư, hay thông tin của bên thứ ba chưa được phép. Khi có rủi ro liên quan đến an toàn, sức khỏe, tiền bạc hoặc các mối quan hệ, hãy liên hệ trước với chuyên gia có đủ chuyên môn hoặc một người hỗ trợ mà bạn tin tưởng.

## 1. Một Câu Hỏi Chính

```markdown
Date range:
The one question this week:
Real situation and audience:
Acceptance standard:
Baseline evidence at the start of the week:
```

Câu hỏi phải có thể quan sát/kiểm chứng được, ví dụ: “Em có thể trình bày một rủi ro của dự án bằng tiếng Anh mà không cần đọc kịch bản và trả lời được câu hỏi hỏi lại không?” Đừng viết kiểu “tuần này em sẽ cố gắng tốt hơn”.

## 2. Ba phiên bản công suất

| Công suất | Khi nào nên dùng | Hành động tối thiểu | Bằng chứng cần giữ lại | Điều kiện dừng hoặc hạ mức |
| --- | --- | --- | --- | --- |
| Ngày đầy đủ | Thời gian và công suất tương đối ổn định | | | |
| Ngày nén gọn | Thời gian ít hoặc sự chú ý bị phân mảnh | | | |
| Ngày phục hồi | Bị bệnh, mất ngủ, đau buồn, hoặc trách nhiệm tăng đột xuất | | | |

Cả ba phiên bản cùng phục vụ một mục tiêu. Ngày phục hồi không phải là thất bại. Khi an toàn, giấc ngủ, sức khỏe thể chất hoặc các mối quan hệ bị ảnh hưởng rõ rệt, hãy bảo vệ những giới hạn đó trước khi hoàn thành kế hoạch.

## 3. Tạo Tiếng Vọng Cho Sự Lặp Lại

| Ngày | Hành động | Gợi nhớ / biến thể / kết quả / phản hồi | Thông tin mới nào đã xuất hiện? | Biến số nào sẽ thay đổi ở lần sau? |
| --- | --- | --- | --- | --- |
| | | | | |
| | | | | |
| | | | | |
| | | | | |

Nếu bốn lần lặp lại không mang lại thông tin mới, hãy đổi chủ đề, người nghe, giới hạn thời gian, số lần gợi nhắc, hoặc quyền dùng công cụ, thay vì vội vàng thêm nhiều lần lặp lại hơn.

## 4. Ghi lại Một Góp Ý Hữu Ích

```markdown
Who or what provided the feedback:
Observation: What did the person actually see, hear, or measure?
Impact: How did it affect understanding, use, or the result?
Next adjustment: Which one important variable will I change?
Evidence location:
```

Khi yêu cầu AI đưa ra góp ý, hãy gửi phiên bản của bạn trước. Chỉ hỏi tối đa ba vấn đề ảnh hưởng đến kết quả, và yêu cầu phân biệt rõ giữa quan sát, suy luận và đề xuất. Con người mới là người quyết định chấp nhận điều gì.

## 5. Gián đoạn và Trở lại

```markdown
What happened, as facts (no character judgment):
Which condition changed: time / capacity / difficulty / environment / responsibility
The smallest return action within 24 hours:
What I will explicitly not make up:
Who I need to contact or which risk needs escalation:
```

Nếu cùng một trở ngại xuất hiện ba lần, hãy thay đổi khung thời gian, quy mô công việc, môi trường, ranh giới hoặc mạng lưới hỗ trợ. Đừng trả giá cho một lần gián đoạn bằng việc thiếu ngủ hay tự dằn vặt bản thân.

## 6. Quyết định trong tuần này

```markdown
One design I will keep:
One demand or entry point I will remove:
One condition I will change next week:
One number I will stop tracking:
Next review date:
First action when I open the file next time:
```

## 7. Bàn giao và Vị trí Lưu Bằng chứng

```markdown
First version:
Revised version:
Feedback or retest:
Next task: owner / date:
```
