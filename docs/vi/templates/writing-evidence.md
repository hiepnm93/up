# Thẻ bằng chứng viết: Từ trau chuốt bằng công cụ đến bàn giao có trách nhiệm

Hãy chép thẻ này vào một ghi chú riêng cho từng nhiệm vụ viết thực tế. Không đưa vào mật khẩu, dữ liệu khách hàng, thông tin của bên thứ ba chưa được phép, đáp án bài thi hay chi tiết cá nhân không cần thiết. Bản cuối cùng có thể công khai mà không cần công khai bản nháp gốc, phần góp ý và hồ sơ sử dụng công cụ.

## 1. Xác định nhiệm vụ, người đọc và trách nhiệm

```markdown
# Writing Evidence - YYYY-MM-DD

Real situation:
Task: explain / request / status / decide / narrate / reflect / hand over
Audience and relationship:
What should they understand, decide, or do afterwards?
Genre, length, and deadline:
Completion standard:
Dictionary / translation / search / AI / human help allowed:
Confidentiality, copyright, privacy, and authorship boundary:
Final accountable owner:
```

Khi một tổ chức, trường học, khách hàng hoặc quy trình tuyển dụng cấm sử dụng sự trợ giúp, hãy tuân theo quy tắc hiện hành.

## 2. Giữ nguyên bản nháp tự soạn

```markdown
Raw draft location:
First-version time and length:
Outline or sources allowed:
One sentence the reader should remember:
Fact I trust least:
Gap most likely hidden by attractive prose:
Action I expect from the first version:
```

Đừng kiểm tra bản dịch theo từng câu trọn vẹn hay nhờ AI soạn văn trước. Hãy giữ các chỗ ngắt nghỉ, sự lặp lại và những đoạn viết chưa đạt làm mốc đối chiếu.

## 3. Lập sổ theo dõi sự kiện và trách nhiệm

| Khẳng định/nội dung | Loại | Nguồn, phiên bản và vị trí | Ngày kiểm tra | Độ tin cậy | Có thể xuất bản? | Điều gì làm thay đổi nó? |
| --- | --- | --- | --- | --- | --- | --- |
| | sự kiện / con số / trích dẫn / trải nghiệm / suy luận / lời khuyên / dữ liệu của người khác | | | | | |

```markdown
What I knew then and learned later:
Third-party content requiring permission:
Part still unverifiable:
Content to remove or anonymise before delivery:
```

## 4. Giữ nguyên khung sườn tài liệu

```markdown
Problem facing the reader:
Direct answer:
Support 1:
Support 2:
Concrete example/minimum fact:
Limit, counterexample, or unknown:
Reader's next step:
```

| Đoạn văn | Chức năng | Phải giữ | Xóa/di chuyển | Lý do |
| --- | --- | --- | --- | --- |
| | ngữ cảnh / vấn đề / khẳng định / lý do / bằng chứng / ví dụ / chuyển ý / giới hạn / yêu cầu / quyết định / bàn giao | | | |

## 5. Ghi lại những thay đổi ý nghĩa khi dịch

| Ý tôi muốn nói | Bản nháp tiếng Anh đầu tiên | Phương án dịch/công cụ đề xuất | Quyết định cuối cùng | Lý do |
| --- | --- | --- | --- | --- |
| | | | | |

```markdown
Did agent or responsibility change?
Was certainty strengthened or weakened?
Did negation or condition scope change?
Does tone fit the relationship?
Non-equivalent institutional/cultural term:
Glossary and reviewer:
```

Tự nhiên, trôi chảy và trung thực là những tiêu chí đánh giá khác nhau. Tác giả ở bản cuối sẽ giải thích sự đánh đổi giữa chúng.

## 6. Hoàn thành năm vòng chỉnh sửa

| Vòng | Vấn đề chính | Trước | Sau | Vì sao nó làm thay đổi kết quả công việc |
| --- | --- | --- | --- | --- |
| Nhiệm vụ và dữ kiện | | | | |
| Cấu trúc và dẫn chứng | | | | |
| Câu chữ và ý nghĩa | | | | |
| Văn phong và giọng điệu | | | | |

```markdown
Necessary correction:

Register choice:

```

## 7. Ghi nhận việc tiếp thu phản hồi

Yêu cầu kể lại trước khi đưa ra nhận xét:

```markdown
Reader's retold point:
Evidence and limits the reader heard:
Next step the reader understood:
Place requiring guessing:
```

| Phản hồi | Nguồn/mối quan hệ | Loại | Quyết định | Lý do | Có được dùng trong văn bản song song không? |
| --- | --- | --- | --- | --- | --- |
| | người đọc thật / bạn đồng trang lứa / giáo viên / biên tập viên / AI | sửa lỗi / mơ hồ / cấu trúc / dẫn chứng / ngữ vị / văn phong | chấp nhận / một phần / từ chối / hoãn lại | | |

Một bản nháp cũ được cải thiện không chứng minh việc áp dụng vào nhiệm vụ mới. Phản hồi chỉ bắt đầu cho thấy sự chuyển giao khi nó được đưa vào một văn bản song song.

## 8. Ghi nhận việc sử dụng AI và các công cụ tự động

```markdown
Tool / model / version and date:
Draft and sources that existed before use:
Request: diagnosis / reader simulation / fact candidate / correction
         / version comparison / counterexample / other
Scope generated or rewritten by the model:
Facts, quotations, or sources it may have invented:
My item-by-item verification:
What I accepted/rejected, and why:
Disclosure required for school, client, employer, or reader:
Parallel task after closing the tool:
```

Kết quả do mô hình tạo ra chỉ là bản dự thảo. Nó không phải là tác giả và cũng không chịu trách nhiệm cuối cùng.

## 9. Kiểm tra giao hàng không đồng bộ

| Mục kiểm tra | Nội dung | Đạt? |
| --- | --- | --- |
| Kết luận/chủ đề tóm tắt trong một câu | | |
| Công việc đã hoàn thành và vị trí bằng chứng | | |
| Rủi ro, điểm vướng mắc và điều chưa rõ | | |
| Ai quyết định cái gì trước khi nào | | |
| Bước tiếp theo, người phụ trách và mốc kiểm tra | | |
| Điều gì xảy ra nếu không nhận được phản hồi | | |
| Xử lý khi thất bại, dừng và quay lại (rollback) | | |
| Liên kết, tệp đính kèm và phân quyền | | |

```markdown
Can the reader continue without another meeting?
Real response or execution result:
Gap that still required oral explanation:
```

## 10. Kiểm tra khả năng ghi nhớ trì hoãn và chuyển giao

| Thời điểm | Nội dung bị loại bỏ | Điều kiện thay đổi | Sản phẩm đầu ra | Kết quả |
| --- | --- | --- | --- | --- |
| Ngày 1 | Không có văn bản do AI viết | Tác vụ gốc | Bản thảo và bản bàn giao | |
| Ngày 3–7 | Đã loại bỏ câu cũ và các nhận xét | Chủ đề mới, cùng thể loại | Văn bản song song | |
| Ngày 14 | Đã loại bỏ nhận xét và bản dịch gần đây | Đối tượng đọc mới, cùng thông tin | Văn bản chuyển đổi văn phong | |
| Ngày 30 | Đã đóng tất cả các đề luyện tập | Email, báo cáo, đơn từ hoặc bàn giao công việc thực tế | Bàn giao hoàn chỉnh | |

```markdown
Structure and judgment available after seven days:
Problem that returned with a new topic:
Did whole-sentence translation/full rewrite dependence decrease?
Did the reader guess less?
One variable for the next cycle:
```

## 11. Chấm điểm và quyết định có nên ký hay không

Điểm 0-2: `0=not completed`, `1=prompt-dependent or unstable`, `2=completed under the current condition`.

| Hạng mục | Ngày 1 | Ngày 7 | Ngày 14 | Lý do dựa trên bằng chứng |
| --- | ---: | ---: | ---: | --- |
| Để lại một bản nháp độc lập | | | | |
| Làm rõ nhiệm vụ, người đọc và bước tiếp theo | | | | |
| Tách bạch sự kiện, nguồn và suy luận | | | | |
| Dùng cấu trúc và bằng chứng để hỗ trợ kết luận | | | | |
| Giải thích các thay đổi từ dịch thuật/AI/phản hồi | | | | |
| Cho người đọc không đồng bộ tiếp tục hoặc quay lại | | | | |
| Bàn giao sau khi thay đổi chủ đề, đối tượng hoặc thể loại | | | | |

```markdown
Current version: willing to sign / needs verification / narrow scope / do not deliver
Most important evidence:
Conclusion I still cannot draw:
Smallest next task:
Next review date:
```
